## Non-blocking follow-ups

1. **Real checkout's `node_modules` is Node-20-ABI and will not run under Node 24.**
   `node -e "require('/home/guilherme/msfslogger/node_modules/better-sqlite3')"` under
   Node 24 → `was compiled against a different Node.js version using NODE_MODULE_VERSION 115`.
   It is a locally node-gyp-built binary (`build/Release/obj.target/` present), not the
   tarball prebuild. Under Node 20 it loads fine, so **the live server is safe** and the
   implementer's risk 1 is resolved — but whoever cuts the server over to Node 24 must
   reinstall `node_modules`, not merely `nvm use 24`. Prebuilds are ABI-pinned per major
   (my scratch prebuild loads on 24, fails on 20 and 26), so this is inherent, not a defect.
   Worth an explicit line in the run's cutover step.
2. **`@types/node` is still `^20.11.20`.** The run targets Node 24 but typechecks against
   Node 20 typings. Outside T-001's stated goal ("no other dependency changes"), so not a
   T-001 defect; a later task should bump it or record why not.
3. **Puppeteer's blocked postinstall is masked locally.** `~/.cache/puppeteer` already holds
   `chrome` and `chrome-headless-shell`, which is why `tests/pdfExport.test.ts` passed in my
   cold scratch clone. A CI runner has no such cache and npm 11 blocks the download script
   by default — the e2e job may fail to find a browser. Hand to T-003 (CI) to verify.
4. **`npm ci` reports 9 vulnerabilities (2 moderate, 6 high, 1 critical).** Pre-existing,
   not introduced by this bump. Its own run.
