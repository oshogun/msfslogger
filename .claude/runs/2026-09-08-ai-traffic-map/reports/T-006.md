# T-006 report — Agent: gather AI traffic from SimConnect and push it, plus docs

## What was built

- `agent/traffic.js` (new) — pure, dependency-free logic: `buildTrafficBatch`
  (design.md §3.8), `TRAFFIC_ENABLED`/`trafficRadiusM` env parsing (§3.5), and
  the `MAX_BATCH_OBJECTS = 200` constant. No `require` of `node-simconnect` or
  anything else.

  `buildTrafficBatch`, and a `postTrafficBatch` that reuses the existing
  `postJson` helper. All edits are additive; nothing existing was changed in
  place (see criterion 6 below).

  §9.2's rows A1–A26 by hand (see file header for why A27/A28 are out of
  scope for this file).
- `agent/README.md`, `README.md` — documented the feature, the env vars, the
  radius/cadence, the "dozens of objects" note, and the "never persisted"
  guarantee; updated the source-tree listings in both places (README.md's is
  around the "Project structure" section).

## Only verifiable on the Windows machine

`node-simconnect` is not installed on this machine (`agent/node_modules` does
not exist) and was not installed as part of this task. The following claims
are implemented per design.md but can only be confirmed against a live
SimConnect connection:

- That `requestDataOnSimObjectType(REQ_TRAFFIC, DEF_TRAFFIC, trafficRadiusM,
  SimObjectType.AIRCRAFT)` actually returns in-range AI aircraft and not, say,
  an empty or malformed sweep — design.md §3.1 documents this from reading the
  `node-simconnect` package source and its own sample, not from a running sim.
- That `simObjectDataByType` delivers exactly one event per in-range object
  plus a final `outOf`-consistent tail, and that an empty sky produces one
  `outOf === 0` event rather than no event at all (§3.6, §10.4 risk table).
- That the user's own aircraft is excluded correctly in practice — guard 1
  (`id === userObjectId`) is implemented and inspector-tested via
  `buildTrafficBatch`, but whether MSFS actually reports a *different* object
  id for the user in an `AIRCRAFT`-type sweep than in the `OBJECT_USER`
  request (making guard 2 load-bearing) is unverified (§3.4, §10.4 risk row 1).
- That `PLANE ALTITUDE`, `GROUND VELOCITY` and `SIM ON GROUND` behave the same
  way for AI objects as they do for the user aircraft (§10.4 risk row 5).
- That the 2 s sweep cadence and the `[Agent] AI traffic gathering disabled
  (TRAFFIC_ENABLED)` startup log line actually appear as designed when
  `agent.js` runs end to end with `node-simconnect` present.
- That `npm start` in `agent/` still connects and logs normally with the new
  `require('./traffic.js')` line added (verified only by `node --check` and
  by code inspection here, not by running the agent).
