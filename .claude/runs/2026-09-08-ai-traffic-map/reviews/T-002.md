## Non-blocking follow-ups

1. **NB1 — §3.8 step 3 does not finite-check `id`.** An object with a non-integer
   `id` survives `buildTrafficBatch` and makes the server reject the *whole*
   batch (§4.6, S18), every 2 s, silently. §3.8 step 6's claim that the agent
   "can never trip the server's 400" covers only the count-based 400. In
   practice `objectID` is a uint32 read, so unreachable — but add `id` to the
   step-3 predicate and soften the step-6 claim.
2. **NB2 — `lastSweepAt`'s initial value is unstated** (§3.6). `0` sweeps on the
   first frame; `Date.now()` waits 2 s. Nothing depends on it; pick one and say so.
3. **NB3 — homes for `roundCoord`/`roundAlt`/`normHeading`/`distanceM` unstated**,
   and `MAX_RETAINED_OBJECTS` is declared in `trafficStore.ts` (§1.2) but used in
   `ingest.ts` (§4.6 step 4). Both files are T-003's, so it is a free choice, not
   a coordination hazard.
4. **NB4 — `express.json()`'s default 100 KB body limit** is not mentioned in
   §4.3, and a 413 is not one of §4.5's rows. A 200-object batch at §8.1's full
   double precision is ~26 KB, so it is unreachable; worth one sentence.
5. **NB5 — §3.6 assumes an `outOf === 0` event is actually delivered** when the
   sky is empty. It is inferred from the package sample's guard, not observed.
   If MSFS delivers nothing instead, the empty batch is never posted and markers
   linger until §5.4's 10 s expiry — self-healing, but not listed in §10.4.
6. **NB6 — §2.3's cross-reference is garbled** ("§8 of this document's sibling
   discussion in §6.5"); it means §6.5.
