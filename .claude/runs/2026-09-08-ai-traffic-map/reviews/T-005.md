5. **Memory-safety judgement**:
   - **Server store bound**: `src/trafficStore.ts` `TrafficStore.replace()` does
     `this.objects = objects` (full replacement, never `push`/`concat` — src/trafficStore.ts:91),
     so there is no code path that accumulates across batches. The retention cap
     (`applyRetentionCap`, src/trafficStore.ts:57-72, `MAX_RETAINED_OBJECTS = 100`) is applied
     in `src/ingest.ts`'s route handler (line ~237, `applyRetentionCap(result.objects, flightManager.appState.lastFrame)`) on **every** accepted batch before `replace()` — so the
     store can never exceed 100 objects, and lazy staleness (`TrafficStore.read()`,
     src/trafficStore.ts:106-111) empties the array entirely after 10s of silence,
     releasing the memory rather than just hiding it. Over an hour of arbitrary churn the
     store is bounded at 100 `TrafficObject`s (~tens of KB) at any instant.
   - **Client Leaflet-layer bound**: `client/src/components/LiveMap.tsx`'s traffic effect
     (lines 82-109) builds a `seen` set from the *current* poll's `status.traffic` (itself
     capped at 100 by the server) and, in the second loop (103-108), calls
     `map.removeLayer(marker)` **and** `trafficRef.current.delete(id)` for every id not in
     that set — removing from both the Leaflet layer group and the ref Map, so neither
     structure can grow past the size of the latest batch (≤100). The unmount effect
     (112-120) removes every remaining marker and clears the ref Map, so navigating away
     leaves zero layers. Confirmed empirically above (1000-id churn test).

## Design conformance spot checks

- `TrafficObject` in `src/types.ts` and `client/src/types.ts` are byte-identical to §2.1,
  neither imports from the other — matches the SimFrame/StatusFrame precedent.
- `/api/status` handler (`src/server.ts`) uses the exact same conditional-spread idiom as
  `plannedLeg`: `...(traffic.length ? { traffic } : {})` — never `null`, never `[]`.
- §4.5 order (auth → kill switch → object shape → objects array → length → per-element) is
  implemented in that exact order in `src/ingest.ts`'s `/traffic` handler and
  `buildTrafficObjects`.
- Rounding formulas (`roundCoord`, `roundAlt`, `normHeading`) and `distanceM` in
  `src/trafficStore.ts` are copied verbatim from §2.4/§5.5, not "simplified."
- Client marker lifecycle (§7.3), icon differences (§7.2 table — font-size, color,
  opacity, filter, iconAnchor, zIndexOffset), and the "never move the map" rule (§7.5 — no
  `setView`/`panTo`/`flyTo`/`fitBounds`/`setZoom`/`invalidateSize` in the traffic effect)
  all match on inspection of the full file (read in full above).
- §7.1 "not touched": the own-aircraft effect (lines 36-73) is unchanged code — same
  null-island guard, same `setView`/`panTo`, same track-polyline fetch, same
  `headingDeg - 90` rotation (post-dating the separate "Fix aircraft icon heading
  rotation" commit, not reverted by this diff).
