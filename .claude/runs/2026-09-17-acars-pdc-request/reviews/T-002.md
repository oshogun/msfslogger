## Non-blocking follow-ups

1. `handleRequestLoadsheet` and `handleRequestClearance` are now identical apart
   from the URL segment, the sentinel and the response type — ~25 duplicated
   lines including the merge reducer and its comment. A third such endpoint
   would make extracting `requestPlannedLegPair(segment, sentinel)` worthwhile.
   Not worth churning an approved diff for now.
2. The button gives no affordance for the 409 `NO_FLIGHT_PLAN` case — a leg with
   no dispatch message shows an enabled button that fails on click into the
   error banner. Acceptable (loadsheet behaves the same way), but if the page
   ever learns whether a flight plan exists, both buttons could gate on it.
3. `ClearanceDetails` / `ClearanceRequestResponse` are now hand-duplicated
   between `src/types.ts` and `client/src/types.ts`, as is every other shared
   type in this project. Parity is correct today; nothing enforces it at build
   time. A shared types package is the standing follow-up, out of scope here.
