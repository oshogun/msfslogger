## Design conformance

- Route path, 404 `PLANNED_LEG_NOT_FOUND`, 409 gate on
  `parseDispatchPayload(dispatchMessage)`, 201/200 by `created`: structurally
  identical to the loadsheet route above it (`src/routes/acars.ts:434-488` vs
  `:495-549`). Verified live: `999999` → 404 `PLANNED_LEG_NOT_FOUND`, `abc` →
  400 `INVALID_ID`.
- Dedup keys as frozen: rows stored under `clearance-req:leg:36` (downlink,
  `pdc`, `REQUEST CLEARANCE`) and `clearance:leg:36` (uplink, `pdc`, `PDC`,
  `correlation_id: 15` = the request's id, `payload_json` = `ClearanceDetails`).
- **409 fires before any insert.** Traced in source (early `return` at
  `src/routes/acars.ts:509`) and confirmed empirically: after the 409 on leg 33,
  `select … where category='pdc'` returned only leg 36's two rows — no orphaned
  downlink.
- `deriveInitialAltitudeFt`: `null→5000`, `min(5000, cruiseAltFt)` otherwise.
  Matches.
- `squawkForLeg`: exhaustively checked legIds 0..20000 — `badFormat=0
  reserved=0`, deterministic. Loop cannot hang: only 4 reserved codes and the
  bump is `+1 mod 4096`, so it exits after at most one iteration; verified the
  four legIds whose raw hash lands on a reserved code — `0→0001`, `832→7501`,
  `1920→7601`, `3008→7701`.
- `buildClearanceDetails`/`buildClearanceBody` are pure (no I/O, no clock) and
  the body renders `????`/`NIL` fallbacks: `buildClearanceDetails(basePayload({
  origin:null, destination:null, route:null }), 1)` → `???? TO ????` /
  `CLEARED VIA NIL`. Disclaimer line present.
- `ingestScope.ts`: the new anchored pattern cannot shadow or be shadowed by the
  `…/acars-messages$`, `…/wx$` or `…/loadsheet$` entries (all `$`-anchored on
  distinct suffixes). `tests/ingestScope.test.ts`'s allowlist is **not** papering
  over a failure — `the allowlist against the real route tables` enumerates
  routes off the live `createAcarsRouter()` express stack and asserts scoped-iff-
  listed in both directions, so the entry only passes because the route exists.
- Types: `ClearanceDetails`/`ClearanceRequestResponse` match the handler's
  constructed object exactly (verified by `tsc` plus the live JSON above).
- No schema change, no new dependency, no `dist/` emission. Confirmed.

## Security

No new exposure. The endpoint is leg-scoped by path, 404s an unknown leg before
reading anything, takes no request body (nothing to inject), and returns only
data derived from the leg's own dispatch payload — already reachable under the
same ingest token via `/loadsheet`. `legId` is `parseInt`-validated and reaches
SQL only as a bound parameter. Nothing new logged.

**Concurrency:** six simultaneous POSTs for one leg → `201` once, `200` five
times, and `select dedup_key, count(*) … group by dedup_key` → exactly 1 row per
key. The partial unique index plus `ON CONFLICT DO NOTHING` holds.

## Non-blocking follow-ups

1. `src/acars.ts:434` — the jsdoc ends `same leg always gets the same code
   (AC2)`. Not one of the prohibited run citations, but `AC2` names a criterion
   in `user_stories/acars_pdc_request.md`, an untracked file; a reader of `src/`
   cannot resolve it. Suggest stating the property instead of numbering it.
2. `src/types.ts:594` types `route: string | null`, but `clampRoute` returns
   `'NIL'` for null and never null — so the `?? 'NIL'` in `buildClearanceBody`
   is unreachable and the type is wider than the value. Cosmetic.
3. `tests/acars.test.ts` — the case titled `carries a null origin, destination
   or route through rather than substituting a fallback` asserts
   `expect(details.route).toBe('NIL')`, which is the opposite of what the title
   claims (the assertion is right; the title is wrong).
4. `squawkForLeg` multiplies by `2654435761` before `% 4096`; above legId
   ≈3.4e6 the product exceeds 2^53 and the low bits are lost (`squawkForLeg(1e15)`
   → `0001`). Output stays a valid, deterministic, non-reserved code, and real
   leg ids are nowhere near this. Note only.
5. The reserved-code bump makes 4 codes collide inside legIds 0..4095 (e.g.
   legId 0 and legId 3921 both emit `0001`); 4092 distinct codes for 4096 legs.
   Squawk uniqueness was never a requirement — recorded so nobody assumes it.
6. `deriveInitialAltitudeFt` passes zero/negative cruise altitudes straight
   through (`-200` → body `CLIMB AND MAINTAIN -200FT`). This is exactly the
   frozen `min(5000, cruiseAltFt)`, so clamping would be a design amendment, not
   a fix. Worth a decision if SimBrief can ever file a non-positive cruise alt.
7. No route-level test covers the new endpoint — `tests/acars.test.ts` exercises
   only the pure helpers (thoroughly: constants, both dedup keys, altitude
   derivation, squawk format/determinism/reserved-avoidance, field mapping,
   fallbacks, disclaimer). That matches the loadsheet route's existing coverage,
   and the four ACs are route-level, which is why they were verified by hand
   here. A route-level suite is the standing gap, not this task's.
8. Out of scope but present in the working tree: `client/src/index.css` and
   `client/src/pages/Home.tsx` are modified and contain no `pdc`/`clearance`/
   `squawk` references — unrelated pre-existing edits, not T-001's. They must not
   be swept into this task's commit.
