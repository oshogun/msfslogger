## Findings

**F1 — §4.2 / §2.3 vs `plan.json` T-005 acceptance criterion (non-blocking for
the design; action required by the Orchestrator before T-005 is dispatched).**
The design freezes output order as `start_time` asc, ties by `id` asc, with
request order explicitly discarded. T-005's third acceptance criterion reads
"multi-flight set with per-flight containers **in the requested order**", which
the design deliberately contradicts. A Dispatcher implementing the design will
fail that criterion as written. Amend T-005's criterion to "in start_time
order (design §4.2)" when dispatching. (T-004's "one container per requested
id" is count-based and does not conflict.)

## Non-blocking follow-ups

- **N1 — §2 / §1.3 item 3 line numbers.** The catch-all is at `src/server.ts:787`
  (design says 786-789) and `slugify` at 43-51 (§3.4 says 40-51). All other
  citations verified exact: `dateStamp` 53-57, `flightExportFilename` 59-65,
  `sendPdf` 67-73, export block 742-784, `/api/flights/:id` 328,
  `POST /api/flights/combine` 163, `downloadPdf` call sites
  `FlightDetail.tsx:215` / `TripDetail.tsx:129`, PDF buttons
  `FlightDetail.tsx:438` / `TripDetail.tsx:735`, filename regex
  `client/src/utils/api.ts:38`, palette `Home.tsx:153` (design says 154).
  Cosmetic drift only; implementers should re-locate by grep, not by line.
- **N2 — §5.1 `flightLabel` escaping.** The design does not say whether
  `flightLabel()` returns raw or escaped text. §4.6 ("escaping applied at every
  interpolation point") plus §5.1's example return value imply raw, with the
  caller escaping — but an implementer who escapes inside the helper will
  double-escape a trip name or aircraft string. Worth one sentence in §5.1.
- **N3 — §7.1 `downloadPdf` signature.** The design writes
  `opts?: { includePlans?: boolean }`; the real code is
  `opts: { includePlans?: boolean } = {}` (`client/src/utils/api.ts:22`).
  Must-not-change item 7 says the signature is unchanged, so T-007 should keep
  the defaulted form verbatim.
- **N4 — §4.3 `????` vs client `???`.** The label uses a four-character
  placeholder while `Home.tsx:173` renders `???`. Deliberate or not, the design
  cites that line as the thing it matches. Cosmetic.
- **N5 — §4.1 fractional seconds.** The rejection of `gx:Track` cites uneven
  viewer support for milliseconds in `<when>`, but `<TimeSpan><begin>` carries
  the same `…:35.639Z` form and the same xsd:dateTime rule. The risk is smaller
  (a viewer that ignores TimeSpan loses nothing), but the argument as written is
  not quite symmetric.
- **N6 — §7.4 zero-point flights.** Rows with `point_count === 0` stay
  un-checkable on Home, so a zero-point flight can never reach the set export
  from the UI even though §6.1 defines its output. Consistent with
  must-not-change item 8; noted so nobody reads it as a gap later.
