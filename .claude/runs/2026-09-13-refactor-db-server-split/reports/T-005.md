## Risks

1. **`MAX_LNMPLN_FILES` has a call site outside the error handler** (`server.ts:441`)
   until the planned-legs router lands in T-007. AC 6's "only in the error
   handler" is therefore satisfied only for `MAX_LNMPLN_BYTES` and
   `MAX_FLIGHT_PLAN_BYTES`. Not a defect, but the Reviewer will see it in the grep.
2. **Runbook amendments.** The runbook's server commands do not start: config
   refuses `BIND_HOST=0.0.0.0` without TLS, and rejects `SESSION_SECRET=s1` /
   `INGEST_TOKEN=t1` as under 16 chars. I used `BIND_HOST=127.0.0.1`,
   `SESSION_SECRET=scratch-session-secret-1`, `INGEST_TOKEN=scratch-ingest-token-1`
   — identical on both servers, so the comparison stays like-for-like.
3. **`client` in the base worktree was replaced by a symlink** to the main
   checkout's `client/`, because `client/dist` is gitignored and the PDF export
   renders the print page from it. Both servers therefore served the same
   `client/dist` — which is what makes the page-count comparison meaningful, but
   it also means the base tree's own client source was never exercised. No client
   code changes in this run, so this is the intended trade.
4. **The base tree was never given a second `?plans=1` trip export.** The trip
   PDF comparison ran only with `?plans=0` (59 pages both) — the full trip export
   with all 54 legs' attachments is a multi-hundred-page render on both servers
   and I judged the cost not worth it. The `appendPdfs` path is covered by the
   flight-1 25-vs-1 comparison instead. Named here as the one thing I chose not
   to run rather than could not.
5. **Router-mount error propagation was verified only for the `express.json()`
   SyntaxError**, which is thrown at app level before routing, so `req.path` was
   never rewritten by the mount in that case. An error thrown *inside* a mounted
   handler relies on express restoring `req.url` when unwinding the router; that
   restoration is not separately exercised by any test here. The 500 branches in
   the export handlers all `res.status(500).json(...)` themselves rather than
   calling `next(err)`, so nothing currently depends on it.
6. **Repo `dist/` now holds this task's output** (`npm run build:server`). The
   user's running server loaded the old `dist/` at 00:11 and is unaffected, and
   `tsc` is clean with 327 tests green — but their next restart runs unmerged
   refactor code. Same standing flag as phase 1.
