# T-001 report — route-table inspector and pre-refactor baselines

## What was built

`src/inspect-routes.ts`: a `ts-node` CLI over the real `createServer()`. It
sets the two env defaults `loadConfig()` needs to not throw
(`BIND_HOST=127.0.0.1`, `ALLOW_UNAUTHENTICATED_INGEST=1`, only if the caller
left them unset), calls `loadConfig()` + `initDb()`, builds the app with a
stub `FlightManager`, then walks `app._router.stack` recursively. A layer with
`.route` is a leaf route; a layer with `.handle.stack` is a mounted
`express.Router()` and is walked with its mount prefix (recovered from the
mount layer's compiled regexp — exact for a plain-string mount with no path
params, which is the only kind used here) prepended. Output is one
`METHOD<TAB>/full/path` line per route, in registration order. It exits
explicitly after printing so `createServer()`'s background timers (session
sweep, ingest-staleness check) never get a chance to fire against the stub
manager and crash the process after the output is already correct.

## A pre-existing tree conflict, and how it was handled

Mid-task, T-002 (parallel) had already rewritten `src/db.ts` into a partial
barrel and added `src/db/*` in the working tree. Building `db-exports.before.txt`
against that tree would have captured the *in-progress* surface, not the
pre-refactor one — the opposite of what this baseline is for. Both baselines
were instead built from a disposable `git worktree add --detach <tmp> 8fcf363`
(current `main` tip, pristine `src/db.ts`), with `node_modules` symlinked in
from the main checkout and `src/inspect-routes.ts` copied over (it's untracked,
so absent from the worktree checkout). The worktree was removed after use;
`git worktree list` in the repo now shows only `main`.

## Risks / assumptions

- **`TS_NODE_FILES=true` is required**, not just `NODE_PATH`/`TS_NODE_PROJECT`.
  Without it, `ts-node/register` invoked via `node -r` never picks up
  `src/auth/express-session.d.ts` (a global ambient augmentation of
  `express-session`'s `SessionData`, not reachable via any `import`), and
  compilation fails with `Property 'user' does not exist on type 'Session &
  Partial<SessionData>'`. This reproduces identically on the pristine
  pre-refactor tree, so it is a pre-existing `ts-node`-vs-`tsc` inclusion gap,
  unrelated to this task's code. Whoever re-runs `routes.before.txt`'s
  producing command later (the reviewer, or a `routes.after.txt` task) needs
  `TS_NODE_FILES=true` set the same way, or the run will fail for an unrelated
  reason and could be misread as a route regression.
- The exact command string in the acceptance criteria
  (`node -r ts-node/register /home/guilherme/msfslogger/src/inspect-routes.ts`
  run from a bare scratch `mktemp -d`) does not work standalone in this
  environment: with no local `node_modules`, `ts-node/register` itself can't
  be resolved, and even with `NODE_PATH` set, `ts-node` cannot find
  `tsconfig.json` by walking up from an unrelated cwd. `NODE_PATH` and
  `TS_NODE_PROJECT` (pointing at the repo's `node_modules`/`tsconfig.json`)
  were added to the same command line; the semantics the criterion cares
  about — cwd is the scratch dir holding the db copy, so `DB_PATH` resolves
  there — are unaffected.
- `db-exports.before.txt` was built from a temporary `git worktree` at the
  current `main` tip (`8fcf363`) rather than the live working tree, because
  T-002 had already rewritten `src/db.ts` in place when this baseline was
  captured. If T-002's changes are ever committed before this baseline is
  consumed, `8fcf363` remains the correct pre-refactor reference commit for
  it (that's what "before" means here) — but this is worth the reviewer
  double-checking against `plan.json`'s definition of the pre-refactor point.
- I did not modify or read `src/db.ts`/`src/db/*` beyond `git diff --stat`
  and `git status` to confirm the conflict existed; no opinion is offered
  here on T-002's in-progress work.
