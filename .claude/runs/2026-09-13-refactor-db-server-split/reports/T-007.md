## Risks

1. **The SimBrief network branch was not exercised.** I asserted only the three
   pre-network validations and did not stand up the stub. So
   `SIMBRIEF_FAILURE_STATUS` (the 400/404/502/504 table) and the
   `SimbriefParseError` → 502 branch moved with the file but were never
   *executed* after the move. The verbatim diff covers them structurally; a
   behavioural check needs the stub or the real service. Named as chosen-not-run,
   not couldn't-run.
2. **`imported_at` differs between the two servers** on every body carrying a
   planned leg. I judged this a clock artefact of two independent databases, not
   a refactor difference, and compared with that one field normalised. If the
   Reviewer wants raw byte-identity there, both servers would need a frozen
   clock.
3. **`refreshPlannedLegForFlight` verified structurally, not behaviourally** —
   same limitation T-006 flagged: on a scratch server with no agent connected
   there is never a flight in progress, so the call is a no-op by definition. The
   handler returned 200 (10-link), so the line is reached.
4. **Only one duplicate shape was tested.** The cross-request duplicate branch
   (`findPlannedLegBySource`) is covered; the *in-batch* duplicate branch
   (`seenInBatch` / `duplicateOfInBatch`, the F-1 fix) was not sent the same file
   twice in one request. Both are verbatim in the diff, but only the first has a
   differential curl behind it.
5. **The route inspector was run once, against the refactored tree only**, and
   compared to the stored baseline rather than to a fresh run of the base
   worktree. That is how T-005 and T-006 did it, so the comparison is
   like-for-like, but the baseline file is trusted rather than regenerated.
6. **Repo `dist/` holds this task's output** (`npm run build:server`). The user's
   running server loaded the old `dist/` and is unaffected, but their next
   restart runs unmerged refactor code. Same standing flag as T-005/T-006.
7. **The inherited T-006 route-table offset is still unresolved.** Criterion 1's
   raw whole-file diff is non-empty for the reason T-006 documented. I did not
   attempt to fix it — it is outside this task's block and the Orchestrator has
   it pending the phase-2 reviewer.
