## Risks

1. **Criterion 1 cannot be met as worded, and I did not block on it.** The plain
   route-table diff is non-empty. I judged it a stale AC rather than a design
   question, because the task's own note says cross-prefix reordering is safe and
   because two routers cannot reproduce a four-block interleaving. If the
   Orchestrator wants a byte-identical table, the only way there is a different
   decomposition (e.g. `createFlightsRouter` split so the `/:id` routes mount
   after the trips router) — say so and I will do it. **T-007 has the same AC and
   will inherit this**, since the planned-legs mount sits where its block already
   was and will not reintroduce the offset.
2. **`refreshPlannedLegForFlight` was verified structurally, not behaviourally.**
   Both call sites are line-for-line identical to the pre-run source and are
   reached (the two handlers returned 200 in criterion 3), but on a scratch
   server with no agent connected there is never a flight in progress, so the
   call is a no-op by definition and its *effect* was not observed. Same
   limitation as any test of this path without a live sim.
3. **`combine` was exercised on flights 74 and 83, not on a synthetic pair.**
   Flight 74 is a real trip-1 leg (`planned_leg_id` null, so no leg link was
   disturbed). Both copies produced the identical result, but the check consumed
   two real rows on the copies — fine, they were thrown away, and the live file
   is untouched.
4. **`GET /api/trips/1` is a 15.9 MB response** and `GET /api/flights/1` 197 KB;
   both were compared byte-for-byte, but only trip 1 and flight 1 were sampled.
   A per-row sweep of all 55 flights was not run.
5. **Repo `dist/` now holds this task's output** (`npm run build:server`). The
   user's running server loaded the old `dist/` and is unaffected, but their next
   restart runs unmerged refactor code. Same standing flag as T-005.
6. **`src/routes/trips.ts:98` changed one comment** from `(db.ts)` to
   `(db/trips.ts)`. Deliberate — the function it points at moved in phase 1 — but
   it is the single non-verbatim line in the move, so the Reviewer will see it.
