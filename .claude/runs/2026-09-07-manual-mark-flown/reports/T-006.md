`plannedLeg` narrowing inside the closure because `plannedLeg` is a `const`;

## Residual risks

1. **Predicate drift** — the client predicate has no compiler link to
   `src/plannedLegClose.ts`. Mitigated only by textual identity with design.md
   §8.1, verified above; the 24-row equivalence is T-008's check, not mine.
2. **The `handCloseEligible` narrowing relies on `plannedLeg` being a `const`.**
   If someone later converts it to a `let`, TypeScript drops the narrowing inside
   the arrow function and the file stops compiling. That is a loud failure, not a
   silent one, but it is a coupling worth knowing about.
3. **Flight 57's `link_source` was flipped to `'manual'` in the scratch copy**
   to isolate the `end_time` clause. The live row is untouched (`flights.db` md5
   identical before and after); a reviewer re-running `drive.js` against a fresh
   copy without that mutation will see flight 57 fail two clauses instead of one,
   and the control still absent.
4. **Not verified:** behaviour on a leg whose status is `'diverted'` or
   `'skipped'` — no such hand-linked, ended fixture exists in the live data, so
   the third conjunct's exclusions were not exercised in the browser. The gate's
   server side covers them (T-004's matrix) and the predicate text is identical
   to the frozen one, but the UI path for those two statuses is unobserved.
